## 1. 목표를 다시 정의합니다

"수익률 최대"를 그대로 목표로 삼으면 과거 데이터에 파라미터를 끼워 맞추게 되고, 백테스트 수익률만 높고 실전에서는 손실이 나는 전략이 만들어집니다. 아래 §2.4에서 실제로 확인했습니다.

그래서 목표를 이렇게 바꿉니다.

> **한 번도 보지 않은 기간(검증 구간)에서, 감수할 수 있는 낙폭 안에서 수익을 최대로 낸다.**

### 채택 기준

새 전략이나 설정은 아래 기준을 **모두** 통과해야 실거래에 넣습니다.

| 기준 | 값 | 이유 |
|---|---|---|
| 워크포워드 검증 구간 수익률 | 플러스 | 학습 구간 성과는 보지 않음 |
| 손익비 (이익 합 ÷ 손실 합) | 1.3 이상 | 우연히 플러스인 전략 걸러냄 |
| 최대 낙폭(MDD) | 15% 이하 | 버틸 수 있는 손실 한도 |
| 수익률 ÷ MDD | 1.0 이상 (연환산) | 위험 대비 수익 |
| 코인 교차 검증 | 6개 코인 중 4개 이상 플러스 | 한 코인에만 맞춘 전략 배제 |
| 비용 스트레스 | 수수료 2배, 슬리피지 3배에서도 손익 0 이상 | 실전 체결 오차 대비 |
| 표본 수 | 검증 구간 거래 30건 이상 | 운으로 나온 결과 배제 |
| 파라미터 안정성 | 주변값(±20%)에서도 기준 통과 | 뾰족한 최적점 배제 |

## 2. 현재 전략 진단 (빗썸 실제 시세)

데이터: 빗썸 BTC·ETH·XRP·SOL·DOGE·ADA 원화마켓

| 봉 | 기간 | 시장 성격 |
|---|---|---|
| 4시간봉 3,000개 | 2025-06-10 ~ 2026-10-23 | 하락장 (단순 보유 평균 −38%) |
| 1시간봉 3,000개 | 2026-06-20 ~ 2026-10-23 | 상승장 (단순 보유 평균 +11%) |

진단 조건: 자본 1,000만 원, 거래당 위험 2%. 1회 매수 상한은 없앴습니다.

### 2.1 현재 전략은 수수료 0.25%에서 손실입니다

| 수수료 | 4h 평균 | 1h 평균 | 플러스 데이터셋 |
|---|---|---|---|
| 0.25% | −8.1% | −15.7% | 12개 중 1개 |
| 0.04% | +4.3% | +1.1% | 12개 중 7개 |

- 1,000만 원으로 1년 반 동안 낸 **수수료가 120만~230만 원**입니다. 손실 대부분이 수수료입니다.
- 승률 31.8%, 평균 이익 +4.79%, 평균 손실 −2.63%. 손익분기 승률은 35.4%라 조금 모자랍니다.

### 2.2 손실의 대부분은 진입 직후 나는 이탈입니다

| 청산 경로 | 건수 | 평균 |
|---|---|---|
| 이탈 후 손절가 도달 | 270 | −2.37% |
| 초기 손절가 도달 | 144 | −2.92% |
| 1차 목표 → 추적 손절 | 56 | +4.58% |
| 1차 목표 → 2차 목표 | 49 | +7.43% |
| 1차 목표 → 보유기간 | 30 | +6.41% |
| 1차 목표 → 본전 | 22 | +1.54% |

목표가 규칙은 잘 작동합니다. 1차 목표에 닿은 거래는 평균 +5% 안팎입니다. 문제는 **진입**입니다. 점수가 높을 때는 이미 많이 오른 뒤라서, 들어가자마자 꺾이는 경우가 대부분입니다.

### 2.3 구조 변경 실험 (손절·목표 규칙은 동일, 진입만 변경)

| 진입 방식 | 수수료 0.25% 4h | 수수료 0.25% 1h | 수수료 0.04% 4h | 수수료 0.04% 1h |
|---|---|---|---|---|
| 현재 (점수 ≥ 35) | −8.8% (2/6) | −13.0% (0/6) | +2.9% (3/6) | +3.7% (4/6) |
| **현재 + BTC 상승장 필터** | **0.0% (4/6)** | **+1.0% (3/6)** | **+8.2% (5/6)** | **+9.9% (5/6)** |
| 20봉 신고가 돌파 + 거래량 | −4.1% (1/6) | −0.4% (2/6) | +0.1% (3/6) | +5.9% (5/6) |
| **돌파 + BTC 필터** | −0.1% (3/6) | **+2.5% (5/6)** | +3.4% (3/6) | +5.9% (5/6) |
| 눌림목 매수 (RSI<45 반등) | −19.1% (0/6) | −10.3% (0/6) | −12.1% (0/6) | −3.8% (0/6) |

괄호는 6개 코인 중 플러스인 코인 수입니다.

- **BTC 상승장 필터**는 BTC 종가가 20일 평균 위일 때만 매수하는 규칙입니다. 4시간봉·1시간봉, 수수료 조건에 상관없이 모두 좋아졌고, MDD도 22% → 12~15%로 줄었습니다. 가장 확실한 개선입니다.
- 눌림목 매수는 이 데이터에서 일관되게 나빴습니다. 기획에서 제외합니다.

### 2.4 파라미터 최적화는 검증 구간에서 무너집니다

4시간봉 앞 절반에서 진입 점수·손절 폭을 최적화한 뒤 뒤 절반에 적용했습니다.

| 코인 | 앞 절반 최적 | 뒤 절반 결과 |
|---|---|---|
| ETH | +21.7% | −11.8% |
| DOGE | +22.7% | −2.2% |
| SOL | +6.9% | −7.5% |
| XRP | +11.3% | −6.3% |

6개 중 4개가 검증 구간에서 손실입니다. **최적화보다 검증 체계가 먼저**입니다.

### 2.5 단일 변수 실험 요약 (수수료 0.25%, 4h 평균)

| 변경 | 결과 | 판단 |
|---|---|---|
| 진입 점수 45로 상향 | −8.1% → +2.5% | 진입을 줄이면 좋아짐 |
| 진입 점수 25로 하향 | → −17.2% | 나빠짐 |
| 손절 3.5 ATR로 넓힘 | → −6.9% | 약간 좋아짐 |
| 손절 1.5 ATR로 좁힘 | → −18.0% | 크게 나빠짐 |
| 저항선 필터 끔 | → −14.6% | 필터 유지 |
| 거래당 위험 4% | → −10.1%, MDD 33% | 위험만 커짐 |

### 진단 결론

1. **비용이 가장 큰 손실 원인입니다.** 수수료를 줄이거나 거래 횟수를 줄이는 것이 1순위입니다.
2. **하락장에 매수하지 않는 것만으로 크게 좋아집니다.** BTC 국면 필터가 가장 확실한 개선입니다.
3. **진입을 더 까다롭게 해야 합니다.** 진입을 늘리면 나빠지고 줄이면 좋아집니다.
4. **청산 규칙은 유지하고 다듬습니다.** 목표가 도달 거래의 수익은 충분합니다.
5. **검증 없이 파라미터를 고치면 안 됩니다.**

> 한계: 4시간봉은 하락장 1년 반, 1시간봉은 상승장 4개월이고 코인은 6개뿐입니다. 방향을 정하는 근거로는 충분하지만 최종 확인은 아닙니다. 1단계에서 수년치 데이터로 다시 검증합니다.

## 3. 수익 개선 항목 (우선순위)

기대 효과와 근거가 강한 순서입니다.

### P1. 거래 비용 줄이기 · 기대 효과 매우 큼

| 방법 | 내용 |
|---|---|
| 수수료 등급·쿠폰 | 빗썸 수수료 쿠폰이나 등급 혜택을 적용하고, 실제 수수료율을 설정에 반영 |
| 지정가 진입 | 매수는 `post_only` 지정가로 최우선 매수호가에 걸고, 일정 시간 미체결이면 취소하거나 시장가로 전환 |
| 체결 수수료 실측 | 실제 체결의 `paid_fee`로 수수료율을 자동 계산해 백테스트 가정과 비교 |
| 거래 빈도 관리 | 진입 기준 상향, 국면 필터로 무의미한 진입 제거 |

손절 매도는 지정가로 하면 체결이 안 될 위험이 있으므로 시장가를 유지합니다. 목표가 매도는 지정가로 미리 걸어 둘 수 있습니다.

### P2. 시장 국면 필터 · 기대 효과 큼 · 근거 강함

- **BTC 국면**: BTC 종가가 20일 평균 위면 상승장으로 보고 매수 허용, 아래면 신규 매수 금지(현금 보유)
- **2차 후보**: BTC 20일 평균의 기울기, 원화마켓 전체 상승 종목 비율(시장 폭)
- 보유 중에 국면이 하락으로 바뀌면 바로 팔지 않고 손절가를 올립니다 (현재의 이탈 경계 규칙과 같은 방식).

### P3. 진입 신호 재설계 · 기대 효과 중간

현재는 점수 하나로 "언제 살지"와 "살 만한 상황인지"를 같이 판단합니다. 이를 세 단계로 나눕니다.

| 단계 | 역할 | 예시 |
|---|---|---|
| 필터 | 매수해도 되는 상황인가 | BTC 국면, 점수 ≥ 기준, 거래대금 하한 |
| 트리거 | 지금 사야 하는가 | 20봉 신고가 돌파 + 거래량 1.5배, 또는 변동성 수축 후 확장 |
| 계획 | 얼마에 손절·익절할까 | 현재 손절가·목표가 규칙 |

두 가지 진입 방식(점수형, 돌파형)을 전략 단위로 분리하고, 같은 검증 기준으로 비교한 뒤 통과한 것만 씁니다.

### P4. 청산 규칙 다듬기 · 기대 효과 중간

| 항목 | 현재 | 개선안 (검증 후 채택) |
|---|---|---|
| 이탈 판정 | 20이평 하향 이탈 1봉 | 종가 기준 2봉 연속 이탈, 또는 거래량을 동반한 이탈 |
| 초기 손절 폭 | 2.5 ATR | 3.0 ~ 3.5 ATR 구간 검증 (넓힐 때 개선 경향) |
| 1차 매도 비율 | 50% | 33% / 50% 비교 |
| 목표가 주문 | 프로그램이 감시 후 시장가 | 지정가로 미리 걸기 (수수료 절감, 체결 확실) |
| 손절 감시 | 5초마다 현재가 조회 | WebSocket 실시간 체결가로 즉시 반응 |

### P5. 여러 코인 운용 · 기대 효과 중간~큼

한 코인만 거래하면 신호가 드물고, 국면 필터를 넣으면 더 드물어집니다.

- **유니버스**: 빗썸 원화마켓 24시간 거래대금 상위 20개. 투자유의·경고 종목과 상장 30일 미만 종목은 제외
- **선택**: 최근 20일 상대강도(BTC 대비 수익률) 상위 종목만 진입 허용
- **동시 보유**: 최대 3~5개
- **총 위험 한도**: 모든 포지션의 손절 시 손실 합이 자본의 6% 이하. 코인끼리 같이 움직이므로 종목 수가 늘어도 위험은 합산합니다.

### P6. 포지션 크기 · 위험 관리 강화

| 항목 | 내용 |
|---|---|
| 변동성 기반 크기 | 현재 방식(손절폭 기준 2% 위험) 유지 |
| 연속 손실 감속 | 4연속 손실 시 다음 거래 크기 절반, 2연승 시 복구 |
| 낙폭 연동 | 계좌 MDD 10% 넘으면 거래당 위험 1%로 축소 |
| 기존 장치 | 일일 −3% 신규 중단, 누적 −15% 킬 스위치 유지 |

거래당 위험을 4%로 올려 보면 수익은 늘지 않고 MDD만 33%로 커졌습니다. 위험을 키워 수익률을 올리는 방법은 쓰지 않습니다.

### P7. 외부 데이터 필터 · 효과 미확인, 검증 후 채택

| 데이터 | 출처 | 쓰는 방법 |
|---|---|---|
| 공포·탐욕 지수 | alternative.me 공개 API | 극단적 탐욕(80↑) 구간 신규 진입 축소 |
| 김치 프리미엄 | 빗썸 가격 vs 해외 거래소 가격 × 환율 | 5% 이상이면 신규 진입 보류 |
| 펀딩비 | 해외 선물 거래소 공개 API | 과열(0.05%↑) 시 신규 진입 보류 |
| 빗썸 투자유의 지정 | 빗썸 API 경고 종목 조회 | 지정 시 신규 진입 금지, 보유분 손절가 상향 |

## 4. 검증 체계 (가장 먼저 만듭니다)

### 4.1 데이터

- 코인별 1시간봉·4시간봉을 수년치 내려받아 로컬에 저장 (매일 증분 갱신)
- 빗썸 캔들 API는 1회 200개, 초당 150회 제한 → 수집기는 초당 5회 이하로 천천히 받음
- 상장폐지 종목도 가능한 한 포함 (살아남은 코인만 보면 성과가 부풀려짐)

### 4.2 워크포워드 검증

```
[ 학습 6개월 ][ 검증 1개월 ]
      [ 학습 6개월 ][ 검증 1개월 ]
            [ 학습 6개월 ][ 검증 1개월 ]  ... 1개월씩 밀면서 반복
```

- 학습 구간에서 파라미터를 고르고, 바로 다음 1개월에 적용한 성과만 이어 붙여 평가합니다.
- 파라미터는 최고점이 아니라, 주변값에서도 성과가 고른 "평평한 구간"의 가운데를 고릅니다.

### 4.3 스트레스·견고성 테스트

| 테스트 | 방법 |
|---|---|
| 비용 스트레스 | 수수료 2배, 슬리피지 3배 |
| 거래 순서 섞기 | 거래 결과 순서를 1,000번 섞어 MDD 분포 확인 (최악 5% 기준) |
| 코인 교차 | 학습에 안 쓴 코인으로 검증 |
| 국면별 성과 | 상승장·하락장·횡보장 구간을 나눠 각각 확인 |

### 4.4 연구 리포트 (대시보드 백테스트 탭 확장)

- 워크포워드 누적 수익 곡선과 학습·검증 구간 표시
- 파라미터 히트맵 (진입 점수 × 손절 ATR)
- 채택 기준 표 (§1)의 통과·실패 자동 표시
- 전략 A/B 비교

## 5. 시스템 기능 기획

| 영역 | 현재 | 추가·변경 |
|---|---|---|
| 시세 | 5초마다 현재가 REST 조회 | WebSocket 실시간 체결가, 끊김 감지 시 REST로 대체하고 신규 진입 중단 |
| 데이터 저장 | JSON 파일 | 캔들 캐시 + 거래·주문 기록용 SQLite |

## 8. 집 PC 운영 설계

### 8.1 가장 큰 위험: PC가 꺼지면 손절이 멈춤

빗썸 API에는 거래소에 걸어 두는 손절(예약·감시) 주문이 없습니다. 주문 종류는 지정가·시장가·최유리·TWAP뿐입니다. 손절가 감시는 프로그램만 할 수 있으므로, PC나 인터넷이 멈춘 동안 가격이 급락하면 손실이 손절폭보다 커집니다.

대응:

| 장치 | 내용 |
|---|---|
| 목표가는 거래소에 미리 걸기 | 1차·2차 목표가를 지정가 매도로 미리 걸어 두면 PC가 꺼져도 익절은 체결됨 |
| 재시작 즉시 점검 | 켜지자마자 현재가가 손절가 아래면 바로 매도. 꺼져 있던 동안 놓친 봉을 다시 계산해 손절가 갱신 |
| 외부 생존 감시 | 1분마다 외부 감시 서비스(예: healthchecks.io)에 신호를 보냄. 끊기면 그 서비스가 휴대폰으로 알림 (꺼진 PC는 스스로 알릴 수 없기 때문) |
| 수동 대비 화면 | 대시보드와 텔레그램에 현재 손절가를 항상 표시. 장시간 끌 때는 빗썸 앱의 예약 주문으로 직접 걸 수 있도록 |
| 외출·장기 부재 모드 | 신규 진입을 멈추고 보유분 손절가를 더 가깝게 올리는 옵션 |

### 8.2 집 PC 설정 체크리스트 (설치할 때 진행)

| 항목 | 설정 |
|---|---|
| 절전 | 절전·최대 절전·디스크 끄기 "안 함" |
| Windows 업데이트 | 사용 시간 지정, 자동 재시작은 사용 시간 밖으로 |
| 자동 시작 | 작업 스케줄러로 로그인 없이 부팅 시 실행, 비정상 종료 시 자동 재시작 |
| 정전 복구 | BIOS의 "AC 전원 복구 시 켜짐" 설정 (메인보드 지원 시) |
| 시간 동기화 | Windows 시간 자동 동기화 켜기 (API 인증 토큰에 현재 시각이 들어감) |
| 대시보드 접근 | 기본은 PC 안에서만 접속(127.0.0.1). 외부에서 보려면 텔레그램 알림으로 대신 |

### 8.3 공인 IP 변경 문제

빗썸 API 키는 허용 IP를 등록해야 하는데, 가정용 인터넷은 공인 IP가 바뀔 수 있습니다. IP가 바뀌면 주문·조회가 `NotAllowIP` 오류로 막히고 손절도 실패합니다.

- 프로그램이 공인 IP 변경과 `NotAllowIP` 오류를 감지하면 신규 진입을 멈추고 즉시 알림
- 가능하면 통신사 고정 IP를 쓰거나, 공유기의 IP가 자주 바뀌지 않는지 미리 확인
- 시세 조회(공개 API)는 IP 제한이 없으므로 알림은 계속 보낼 수 있음
