# AST 자동매매 (빗썸 · 코인)

빗썸 API 2.0으로 원화 마켓 코인을 자동 매매합니다. 기술 지표 8종을 점수(−100~+100)로 합쳐 매수를 판단하고, 매수와 동시에 **손절가**와 **목표가(매도가)** 를 정해 관리합니다. 외부 패키지 없이 Node.js 20 이상만 있으면 됩니다.

## 실행

```bash
cp .env.example .env      # 설정 복사 (기본: 모의투자)
npm test                  # 규칙 테스트
npm run backtest -- 1000  # 빗썸 실제 시세 최근 1,000봉으로 백테스트
npm start                 # 자동매매 + 대시보드 http://127.0.0.1:8787
```

기본은 **모의투자(paper)** 입니다. 빗썸 실시세를 받아 가상으로 체결하며 기록은 `data/paper/`에 쌓입니다.

## 매수 판단

봉(기본 4시간봉)이 마감될 때마다 점수를 계산합니다. 미완성 봉은 쓰지 않습니다.

| 지표 | 가중치 | 지표 | 가중치 |
|---|---|---|---|
| 이평선 배열 (20·60) | 15 | ADX/DMI (추세 강도) | 12 |
| MACD | 15 | 거래량·OBV | 12 |
| RSI (국면별 해석) | 12 | MFI | 6 |
| 볼린저밴드 (국면별 해석) | 10 | VWAP | 6 |

점수가 `ENTRY_SCORE`(기본 +35) 이상이면 매수합니다.

- **전략 선택** `STRATEGY`: `score`(위 점수) 또는 `breakout`(직전 20봉 고가 돌파 + 거래량 1.5배 + ADX 20 초과)
- **BTC 국면 필터** `REGIME_FILTER=btc`: BTC 종가가 `REGIME_DAYS`(20)일 평균 아래면 신규 매수를 하지 않습니다. 보유 중인 포지션은 손절가·목표가 규칙대로 관리합니다. 매수 금액은 손절가에 걸렸을 때 자본의 `RISK_PER_TRADE`(2%)만 잃도록 계산하고, 1회 최대 매수 금액은 `MAX_POSITION_KRW`로 제한합니다.

## 손절가

매수할 때 정합니다.

- **초기 손절가**: `진입가 − ATR × 2.5`와 `최근 10봉 저점 − 0.3 ATR` 중 진입가에 가까운 쪽. 다만 진입가에서 최소 1 ATR은 떨어뜨려 잡음에 털리지 않게 합니다.
- **이탈 시 바로 팔지 않습니다.** 점수가 −20 이하로 떨어지거나 종가가 20이평을 하향 이탈하면, 그 봉의 `종가 − ATR × BREACH_ATR(1.0)`를 새 손절가로 정합니다. 가격이 거기까지 **더 떨어질 때만** 매도합니다.
- 1차 목표 달성 후에는 **본전**으로, 이후에는 최고 종가 기준 **추적 손절가**로 올립니다.
- 손절가는 올리기만 하고 내리지 않습니다.
- 현재가를 `PRICE_POLL_SEC`(5초)마다 확인해, 손절가 이하가 되면 시장가로 전량 매도합니다.

## 목표가 (매도가)

위험폭 `R = 진입가 − 손절가` 기준입니다.

- **1차 목표가** `진입가 + 2R`: 도달하면 50% 매도하고, 손절가를 본전(수수료 포함)으로 올립니다.
- **2차 목표가** `진입가 + 4R`: 남은 수량을 전량 매도합니다.
- **저항선 반영**: 최근 60봉 고점이 진입가와 1차 목표가 사이에 있으면 1차 목표가를 저항선 바로 아래로 당깁니다. 저항선이 너무 가까워 손익비가 `MIN_RR`(1.5) 미만이면 **매수하지 않습니다**.

## 성공·실패 판정

포지션이 모두 청산되면 확정됩니다. 수수료·슬리피지를 뺀 순손익이 0원보다 크면 **성공**, 아니면 **실패**입니다. 대시보드에 총 손익, 수익률, 승률, 손익비, 최대 낙폭을 집계합니다.

## 계좌 보호

- 일일 손실 3% 도달 시 그날 신규 매수 중단
- 누적 손실 15% 도달 시 킬 스위치: 전량 매도 후 정지
- 대시보드의 **신규 진입 일시정지**: 새 매수만 멈추고, 보유 포지션의 손절가·목표가 매도는 계속 작동

## 실거래로 전환하기 전에

1. 빗썸에서 API 키를 발급할 때 **자산 조회·주문 권한만** 주고 출금 권한은 주지 마세요. 허용 IP도 등록하세요.
2. `.env`의 `FEE_RATE`를 본인 계정의 실제 수수료율로 맞추세요. 기본값 0.25%는 보수적인 가정입니다.
3. 모의투자로 최소 몇 주 운영해 대시보드 기록을 확인하세요.
4. `MODE=live`, `LIVE_CONFIRM=YES`, 키 두 개를 넣고 `MAX_POSITION_KRW`를 작게 시작하세요.
5. 봇 전용 계정을 쓰거나, 같은 코인을 수동으로 거래하지 마세요. 평가금액에 계좌 전체 잔고가 들어갑니다.

아직 실제 키로 검증하지 않은 부분이 있습니다. 소액으로 먼저 확인하세요.

- 주문 생성은 `/v2/orders`이고, 주문 조회는 문서상 `/v1/order?uuid=`입니다. v2 주문의 `order_id`로 v1 조회가 되는지 확인해야 합니다.
- `price`·`volume`을 문자열로 보냅니다. 문서 스키마는 문자열인데 예시 코드는 숫자를 씁니다.
- 손절가·목표가는 거래소 예약 주문이 아니라 프로그램이 감시합니다. **프로그램이 꺼져 있으면 손절이 작동하지 않습니다.**

## 구조

```
src/
  bithumb/auth.js     JWT(HS256) + query_hash(SHA512)
  bithumb/client.js   시세·계좌·주문 API
  indicators.js       이평·볼린저·MACD·RSI·ATR·ADX·OBV·MFI·VWAP
  strategy.js         판단 점수, 진입 계획(손절가·목표가)
  position.js         손절가·목표가 관리 규칙 (백테스트·실매매 공용)
  backtest.js         봉 단위 백테스트, 성과 집계
  trader.js           실시간 매매 루프, 계좌 보호
  broker/paper.js     모의 체결
  broker/live.js      빗썸 실주문
  server.js           대시보드 API
web/                  대시보드 화면
test/                 규칙·API·통합 테스트
```
